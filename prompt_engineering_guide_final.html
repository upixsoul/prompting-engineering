1) What is Prompt Engineering?

Prompt Engineering is the practice of designing instructions so that an AI model produces more useful, relevant, and consistent responses.

A good prompt reduces ambiguity, defines the goal, provides enough context, specifies the expected output format, and makes clear what to do if information is missing.
Think of a prompt as a short specification: it is not just “asking something”, it is designing an input that correctly guides the model’s behavior.

🌍 Context

Information that helps the model respond better.

📥 Input Data

The text, code, or question the model will work on.

📤 Output Format

How the response should be structured.

🧪 Examples

Demonstrations of expected inputs and outputs.

✅ Validation / Fallback

What to do if information is missing or confidence is low.

If data is missing, state your assumptions.
If you cannot verify it, say so explicitly.

3) Prompt Categories

🌐 Open-ended

When: Ideation, exploration.

What frontend frameworks should I learn?

✅ Close-ended

When: Precise answers.

What is the primary database in AWS?

🧩 Multi-part

When: Multiple outputs in one prompt.

Suggest some technologies I can use for data visualization

That’s the first part, now the second:

And list their strengths and weaknesses

🎯 Scenario-based

When: The scenario is used to set the context within which we want the information that we are querying for. Scenario-based prompts are useful for testing problem-solving skills or exploring hypothetical situations. 

I’m hosting a birthday party. They are all between 11 and 13 years old.

That’s the scenario. The second line is the question:

Based on this scenario, what do you think I should organize? What food do you suggest? I have to ensure that they all have a good time.

💭 Opinion-based

When: Subjective insights.

Do you think microfrontends are worth it?

5) Roles in Chat Prompts

System

Defines general behavior, boundaries, tone, and output format.

You are a technical assistant. If there is not enough information, ask or say "I don't know".

User

Contains the request, context, and materials.

Analyze this Vite compilation error...

Assistant

Can be used for previous examples or conversation history.

Example response showing the desired format.
A system message helps steer the model, but it does not guarantee full compliance. That is why testing, measuring, iterating, and adding validation are still important.

6) Design Patterns That Work

  • Put the instruction first whenever possible.
  • Use delimiters to separate context, data, and rules: ###, <data>, etc.
  • Specify the output contract: JSON, bullets, table, steps, checklist.
  • Define fallback behavior: what to do if information is missing or the request is out of scope.
  • Break down complex tasks into subtasks if one prompt becomes too large.
  • Iterate: test a simple version → improve context → add examples → refine format.

8) Zero-shot, Few-shot, and Chain-of-Thought

🔹 Zero-shot

Give only the instruction, with no examples. Works well for simple or common tasks.

Classify the sentiment as Positive, Neutral, or Negative.
Text: "The product is okay, but I expected more."

🔹 Few-shot

Add examples to control format or improve consistency in more sensitive tasks.

Input: "Hello, send it today"
Output: "Could you please send it today?"

Input: "Send me the file now"
Output:

🔹 Chain-of-Thought (CoT)

Useful for step-by-step reasoning, debugging, or problems with multiple stages.

Solve the problem step by step and then provide the final answer.
If zero-shot does not work well, try few-shot. If few-shot still fails on complex tasks, break the task down or use chaining.
Important note: in some modern reasoning models, overloading the prompt with complex techniques may not help. Clear and simple instructions often work best.

9) Prompt Chaining

When a task is too large for a single prompt, it is often better to divide it into steps.

Step 1

Extract relevant information.

Extract the relevant quotes from the document to answer the question.

Step 2

Use the extracted content to build the response.

Based on the extracted quotes, answer the question with a clear and precise tone.
Benefits: more control, more transparency, easier debugging, and better reliability.

10) Generated Knowledge and RAG

🧠 Generated Knowledge

First, ask the model to generate or list relevant knowledge, then reuse that information in a second prompt. 

Step 1:
Generate 5 key facts about Kubernetes for a frontend developer.

Step 2:
Use ONLY those facts to write a short and clear explanation.

📚 RAG (Retrieval-Augmented Generation)

Instead of relying only on the model’s internal knowledge, retrieve information from documents or external sources and ask it to answer based on them. 

Answer ONLY with the information included between ###.
If the answer is not found, say "Not found in the context".

###
[document or excerpts]
###
Use RAG when you need fresh data, internal documents, policies, or verifiable content.

12) Best Practices

  • Start simple and improve iteratively.
  • Be specific, but avoid irrelevant detail.
  • Use examples when format matters.
  • Define tone, audience, and technical level if that affects the answer.
  • Specify what to do if context is missing.
  • Avoid contradictory instructions.
  • Validate critical outputs: AI can sound confident and still be wrong.
Practical rules: “be clear”, “define the format”, “delimit the context”, “iterate”, “validate”.

16) Final Quality Checklist

  • ✅ Is the task clear?
  • ✅ Is there enough relevant context?
  • ✅ Is the input clearly delimited?
  • ✅ Is the output format specified?
  • ✅ Are useful constraints included?
  • ✅ Is it clear what to do if information is missing?
  • ✅ Does the prompt avoid contradictions?
  • ✅ Does the output require human validation?
